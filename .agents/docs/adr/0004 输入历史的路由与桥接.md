## 输入历史的路由与桥接

输入历史做成 `!` 前缀的第四条路由，而不是面板的第二种模式。前缀和 `>`、`+` 共用同一套认领与最长匹配规则，输入框里始终看得到当前列表；应用命令与 `/history` 只负责用 `!` 播种查询，用户删掉前缀就直接回到会话搜索。

实现注记: 路由层的 `/history` 已由 ADR 0013 移除，模块目录由 ADR 0016 改为扁平结构，本文的路由部分只保留历史；桥接行为仍然成立。

历史数据只有会话消息，而面板挂在根级 `shell.overlay`，拿不到 `useChat`、`useInput` 与 `inputActions`。因此在 `conversation.input.overlay` 常驻一个不渲染的桥接组件，把提示词、草稿、发送阶段与分页标志发布到插件自己的 store，面板只读 store，写回与补页也通过 store 委托给桥接。考虑过从 `uiConversation.binding` 直接读，但那是未列入服务目录的内部面，还要自己重建文本投影与分页状态。

选中历史条目只替换输入框草稿，不关闭面板，这与会话行和命令行「选中即离开」相反。历史是挑文本，用户可能连续试几条，草稿行也只有在面板不关时才回得去；Esc 之后才恢复焦点。草稿行固定为打开面板那一刻的文本，之后写回的文本不改变它，这样它始终是一步可回退的原点。

代价是面板与桥接组件之间多了一个 store，以及 `!` 路由只能搜到已加载的窗口；更早的提示词要用「加载更早」逐页拉，打开时不做后台补页，避免深会话拖慢面板。
