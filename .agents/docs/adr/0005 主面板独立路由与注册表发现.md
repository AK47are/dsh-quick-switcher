## 主面板走独立路由

实现注记：1.0.0 起主面板行由 `src/modules/panels` 提供，注册表发现方式不变。

主面板（插件、自动化任务等）由 DSH 侧栏的 `sidebar.panellist` 列表统一注册，布局再用同一个 id 打开。切换器因此直接读注册表 `ctx.slots.entriesOfSlot("sidebar.panellist")`，再用 `ctx.layout.selectPanel(id)` 打开，而不是写死一份主面板清单：任何插件贡献的主面板都会自动出现在 `#` 路由里，卸载后也不会留下幽灵行。

主面板没有会话状态、工作区与访问时间，混进默认列表会让置顶行同时指会话与主面板。独立路由把这个区别留在结构上，会话列表的排序与置顶语义一个字都不用改，也不需要发明一个同时指会话与主面板的统称。

### 考虑过的替代方案

- 混进默认会话列表：当时讨论过引入「目的地」统称让置顶行跨两类比较访问时间，但主面板本身没有任何状态可以参与排序，而且用户更希望两类目标各自有稳定的位置
- 写死 plugins 与 schedules 两个 id：第三方插件注册的主面板永远不会出现，正是这个需求想避免的
- 直接渲染侧栏注册的图标组件：`renderSlot` 只发给侧栏组件，插件拿到的注册项不含渲染入口，属于未公开用法

### 结果

注册项除 id 与 label 外，代码还会读取 order。标签可能是字符串、函数或语言映射。DSH 自己的 `resolveSlotLabel` 在 `dsh-client-ui-slots` 里，本插件的 bundle 只外置 react 与 primitives，因此三种形态由 `src/modules/panels/logic.js` 自己解析；DSH 改变标签约定时需要跟进。
