## 构建产物不入库

`client.js` 是 esbuild 从 `src/plugin.js` 打出的单文件客户端半区，DSH 的 modules 加载器按 `package.json` 的 `exports["./client"]` 读取它，从不构建，也不接受 `src/` 的相对 ESM 图。仓库因此用 `/client.js` 忽略它：每个提交不再拖着近 100 KB 的不可读 diff，合并时也不必为生成文件解冲突。

代价是克隆之后必须先构建。`package.json` 的 `prepare` 让 `npm install` 顺带生成产物，README 的构建段写明这一步。本目录装进 profile 走 pnpm 的 `link:`，那种依赖只建符号链接、不跑任何生命周期脚本，`prepare` 不会触发，所以本地安装仍需手动 `npm run build`；缺产物时 DSH 会在启动阶段直接报错，不会静默跳过。

替代方案是提交产物，那样仓库随时可加载，但每改一行源码都要提交一份生成文件。另一个替代是改成 git URL 安装好让 pnpm 跑 `prepare`，可这个仓库没有远端，为一条构建钩子引入分发形态不划算。
