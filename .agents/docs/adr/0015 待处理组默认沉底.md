## 待处理组默认沉底

空查询里，待处理组原来和其他组一样按访问时间倒序，于是用户打开一条暂时处理不了的待审批会话后，这一行反而升到组首，把其他还没看过的待处理会话挤下去。现在默认改成最久未访问优先：没打开过的排最前，打开过的按访问时间从旧到新往后沉，打开这个动作只能让一行往后走；设置里可以切回最近访问优先，只影响这一组，其他组、置顶行与三种待处理类型之间的等价关系都不变。

没有改成按更新时间排序：更新时间衡量内容变化，一条等了很久的会话反而会被刚动过的会话压下去，而用户要的是「哪些还没看过」。也没有按进入待处理的时刻排：插件只能从状态跃迁里自己记时间，面板打开前就在等的会话拿不到起点，收益抵不上一个新时钟。

设置项存在浏览器本地，没有走 Host 设置文档。客户端插件要在 Host 侧声明配置字段就得解析 `@deepseek-ai/cordis` 的 Schema，而这个 bundle 只能解析 Node 内置模块；换成 Host 文档能让偏好跨浏览器一致，但为一个排序开关不值得引入这个依赖。
