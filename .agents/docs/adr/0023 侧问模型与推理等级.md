## 侧问模型与推理等级

侧问默认跑会话模型，但档位从会话自己的档位降到该模型支持的最低档：侧问的用处是就眼前的事情马上给答案，跟主对话抢同一个高档位只会更慢。设置页因此多出「侧问模型」与「推理等级」两项，前者默认跟随会话，后者没有「跟随会话」这一项，会话档位永远不参与。

档位 id 由各 provider 适配器提供，DSH 没有跨适配器的档位枚举，也不做夹取或别名。插件按 off、minimal、low、medium、high、xhigh、max 这套顺序比较，模型不支持所选档位时向下取最近的可用档，没有推理能力的模型不传档位；未知 id 按适配器声明顺序排在已知档位之后。模型本身不可用则不同：它是用户特意选的，回退到会话模型会给出他没要的速度与价格，所以直接返回 409 并指向设置页。宿主还必须自己校验，因为 `llm.stream` 会把适配器拒绝折成一条 finish 块，不校验就会显示成没有内容的「完成」答案。

代价是设置页依赖 `remote.session.modelCatalog()`，目录不可用时只能选跟随会话；两个字段用 custom 控件而不是给核心加一种字段类型，设置页因此没有这块的渲染测试；候选档位随模型变化，换模型后旧档位要靠宿主的向下取档兜住。设置只存在浏览器本地，模型与档位随请求体发给宿主，与 ADR 0019 一致。
