## 侧问答案复用渲染器

侧问答案原来由插件自写的迷你渲染器画，它把链接色写成 `--dsw-alias-brand-primary`，而 DSH 把这个 alias 指向 `--dsw-alias-label-primary` 同一个静态色，链接画出来和正文一模一样；强调分支又排在链接分支前面，一段粗体里的链接会被整段吞掉，表格、裸 URL、角括号自动链接、公式与代码高亮也都没有。现在把这份渲染器整体删掉，答案交给会话面板同一个 `MarkdownText`（`@deepseek-ai/dsh-client-ui-primitives`），插件只提供代码块与脚注的文案标签。

组件从宿主运行时的静态模块表取：打包产物已经把 `@deepseek-ai/dsh-client-ui-primitives` 标成 external，`src/core/panel/rows.js` 也已经在用同一个包的 StateDot。`.markdown` 的样式是 shell 的全局样式表而不是组件注入的，同一个文档里自动生效，所以链接色、字重、hover 虚线下划线、表格横向滚动与代码高亮都不需要插件复制。侧问不在 ChatView 的委托树里，因此不提供 `MarkdownDelegateProvider`：http(s) 锚点自带 `target` 与 `rel`，桌面端的窗口打开处理器把它交给系统浏览器；文件类链接退化成纯文本，不在面板里打开右侧栏。答案在流式期间传 `streaming`，结算后走一次完整解析，公式与文件识别在结算那次出现。

代价是多一条对 primitives 公开面与 labels 形状的依赖：围栏代码块与脚注会读 labels，缺 code 对象会直接抛错，DSH 改名或改形状时必须回归；答案排版跟随 DSH 的内容字体设置，卡片不再有自己的紧凑字号。备选是只把链接色换成 `--dsw-alias-link` 并修强调嵌套，改动小一些，但表格、自动链接、公式与代码高亮仍要一项项追，自写渲染器继续背着解析债；另一条备选是复用组件并接管文件链接与右侧栏打开，代价是模态面板下打开的目标被遮罩挡住，交互得改成先关面板。
