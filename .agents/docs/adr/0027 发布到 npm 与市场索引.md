## 发布到 npm 与市场索引

插件原先只作为本地目录装进 profile，仓库没有远端，也没有版本发布。公开之后，安装路径必须让陌生人一条命令装完，而 DSH 的市场只读用户自己配置的 format 1 索引，索引条目的 `source` 只有 npm 与 git 两种。选择 npm 作为主分发，索引随仓库提交，git 源只作为备用。

npm 源的关键作用不是省掉克隆，而是省掉构建。git 源安装时 pnpm 11 会拦下 git 包的 `prepare`, 用户在插件管理器里先看到一批 `pendingBuilds`, 必须点「允许这些脚本并重试」才会跑 `scripts/build.js` 生成 `client.js` 与 `host.js`; esbuild 还要求得下来。npm tarball 没有这一步。因此两份产物仍然不进 git（ADR 0010）, 但进 npm 包的 `files`; 发布前由 `npm run build` 生成, 安装到的就是成品。

索引写在 `market/index.json`, 由 `scripts/market-index.js` 生成: 从 package.json 取版本、engines 与仓库地址, 追加一条 npm source 的记录, 保留旧版本, 再用 DSH 自己的 `@deepseek-ai/dsh-plugin-market-index` 校验整份文档。校验器作为 devDependency 钉死版本, 只用于本地与 CI, 不进包。索引里的 `publishTimestamp` 在发布时重生成, 平时提交的值只是占位。CI 跑 `npm run market:check`, 版本号涨了而索引没跟上会直接失败。

用户把 `https://raw.githubusercontent.com/AK47are/dsh-quick-switcher/main/market/index.json` 加进 Discover 就能看到并安装。这只覆盖愿意加索引的人; 默认市场是社区目录 awesome-dsh-plugin, 收录另外提交。两条路都指向同一个 npm 包, 所以索引与目录都只是发现层, 换掉任何一个都不影响已安装的用户。

文档全部由 AI 生成, 统一放在 `.agents/docs/`: `adr/` 放决策记录, 两篇设计文档与使用、扩展两份指南各有一份中文与一份 `.en.md` 英文。根目录只留 `README.md`, 中文为主, 英文版是 `README.en.md`, 两份顶部互相跳转。`.agents/` 其余部分只留临时沙盒与 worktree, 目录本身也表明除 README 之外的文档都出自 AI。代价是每改一条行为要同步两份 README 与两份指南, 换来的是中文访客第一眼可读, 英文访客也能直接切过去。ADR 与词表保持中文, 它们是决策记录, 不承担上手入口。

放弃了三条路。只发 git 源, 安装多一步审批且依赖网络构建, 与「装上即能用」冲突。把构建产物提交进仓库, 直接违反 ADR 0010, 每次改源码还会让 diff 膨胀。把索引放进独立仓库或 gh-pages, 发布跨两处, 收益只有索引 URL 更短。

`engines.dsh` 定为 `>=0.2.2-0`: 新建会话依赖 `uiWorkspace.startSession`, 更早的版本装上也会在运行时失败, 不如在安装前拦住。`engines.node` 为 `>=20`, 测试与构建脚本用到 Node 20 之后才稳定的接口。
