## 先以 git 源分发

ADR 0027 选 npm 作为主分发，理由是安装不需要跑构建。首次发布时 npm 要求发布级 2FA，命令行拿不到一次性验证码，包没有发出去；项目还在早期，为了不让分发卡在一个只有账号主人才能完成的动作上，暂时改用 git 源，等插件成熟再恢复 npm。

分发方式因此变成：README 以源码安装为主，克隆后 `npm install` 生成 `client.js` 与 `host.js`，再把目录作为本地 bundle 装进 profile。市场索引仍然保留，但条目里的 `source` 从 npm 改成钉住 commit 的 git 地址，这样 Discover 里也能装。git 源的代价是 pnpm 会拦下 `prepare`，用户必须在插件管理器里允许构建脚本并重试；这是唯一比 npm 多出的一步。

索引脚本默认按 git 源生成，`MARKET_SOURCE=npm` 可以切回 npm。git 源的时间戳取该 commit 的时间，不随生成时刻变化；每次发版都要重新生成索引，让 commit 前进到当前版本。索引提交本身在发布提交之后，所以钉住的是上一个 commit，代码内容不受影响。

恢复 npm 时要做三件事：`MARKET_SOURCE=npm npm run market` 把条目换回 npm，README 重新加上按包名安装的段落，ADR 0027 的推理仍然成立，不需要新的决定。社区目录 awesome-dsh-plugin 目前只收录 npm 包，因此也等 npm 恢复后再提交。

放弃的两条路：先在本地建一个带 bypass 2FA 的 granular token，风险是一旦泄露等同发布权限；或者只把仓库转 public、不提供市场索引，那样 Discover 里根本看不到这个插件。
