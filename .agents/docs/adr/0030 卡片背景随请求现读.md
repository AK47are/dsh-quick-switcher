## 卡片背景随请求现读

审批、提问与计划审阅卡片上的正文原先作为 `context` 与 `contextLabel` 存在记录里：详情里显示成可展开的「已附带」，重新生成原样重发，分叉写进新会话。现在它按会话上下文同等处理：只在发问与重新生成的那一刻现读，随当次请求发送，不进入记录，也不在侧问界面单独显示。

理由是一致性。界面已经显示了那张卡片，记录再存一份就是第二个会过期的描述；重新生成是一次新的请求，模型应当解释用户此刻看到的卡片，而不是几分钟前那张。记录落盘之后这个理由更强：刷新恢复的记录没有旧背景可放，与其只对一半记录显示「已附带」，不如统一不显示。

代价是恢复的记录无法回看第一次发问时的卡片，分叉消息也不再带背景，宿主 `/fork` 不再处理这个字段；重新生成时卡片可能已经换了一张，答案依据会跟着变。分叉不现抓，因为分叉写的是用户当时读到的问答，不是一次新的询问。
