## 宿主路径补全端点

绝对路径补全与递归建目录需要文件系统访问。DSH 的 `uiWorkspace.listDirectory` 只在浏览式目录选择器装配时可用，本机回环的 Windows 宿主装配的是原生选择器，调用会得到 `directory-picker/unavailable`；`fileReferences` 只按会话工作目录检索，工作区路径还可能落在它之外。手工改 `.dsh/storages/workspace.json` 也不行：storage-domain 对同一 unit 单开，手改 JSON 还会触发启动时的顺序与重复校验。

决定：插件宿主半区新增两个同源端点，一个列目录、一个递归建目录。它们只接受完全限定路径，目录读取先 `realpath` 再 `stat` 与 `readdir`，跟随符号链接，单目录最多返回 500 条；建目录只在 Enter 提交「新建目录并作为工作区」行时发生，不会因为列目录而改盘。

客户端按行决定动作：普通目录与「已有工作区」直接调用 `workspaces.create`，标了会创建目录的行先 POST 建目录再 `create`，成功后 `uiWorkspace.startSession` 并在新工作区关闭面板。这样写入口仍然只有 DSH 自己的客户端服务，插件的端点只解决「看目录」和「补一个不存在的目录」两件事。

代价是宿主半区必须加载且与客户端同版本，端点不把路径限制在工作区内，和 DSH 自己的 `create` 一致；因此两端都做同源校验，列目录只回目录不读文件内容，权限错误逐条回给列表，客户端在错误时留在面板里说明原因。
