This file is the complete behavior reference for Quick switcher: the input, Enter and shortcut details of every mode, the ordering and display in each state, and the known limits. Getting started needs only the install steps and main flow in the README; come back here when you want to confirm one boundary behavior.

## Use

On any page press Ctrl+Shift+K to open the panel, then type keywords to filter the default session list. The arrow keys move up and down, Enter opens the selected session, and Esc closes. The input takes focus automatically when the panel opens, and closing returns focus to the control that had it. The first row is always the previous session and carries the "Previous" label on its right; press Enter right after opening to jump back. The gray short code after the time on each row is the first segment of the session ID; paste the full ID from "Copy Session ID" in the Sidebar row menu and that session is found directly.

Which mode the general shortcut opens into when it goes from closed to open is decided by "Default mode" in Settings, and the default is the session list. The "Modules" list at the top of Settings can switch any module off or on at any time: an off module stops answering its input prefix and its shortcut, and its preferences stay saved; Settings explains what turning it off means and warns when a module it depends on is off. Every module that is on has a "Quick switcher: <mode>" command in "Edit shortcuts", unbound by default; record a combination with a modifier and it jumps straight to that mode, and pressing it again while already in that mode closes the panel. Turning the module off removes that command from the list, and turning it back on restores the recorded key.

The first nine rows show the platform's jump hint as a capsule on the right: Alt + 1 to Alt + 9 on Windows, and ⌥ 1 to ⌥ 9 on macOS. Holding Alt while pressing the matching number runs that row, the same as pressing Enter on it. Rows from the tenth on have no hint; the numeric keypad does not count, and Alt+Shift+number still runs the primary action.

Typing `+` shows only workspaces, filtered by title or path. Enter opens that workspace's session list; Shift+Enter and Shift+clicking a row enter the new-workspace mode with that workspace's parent directory.

After entering a workspace, the input keeps a scope token such as "+Workspace title " and further typing filters only that workspace's sessions. Deleting the space after the title returns to the workspace list. The scope list always starts with a "+ New session" row; select it and press Enter to create one.

Typing `=` enters the new-workspace mode and lists directories by path. Coming from a workspace row with Shift+Enter, the input already carries its parent directory; typing `=` directly or using the mode command starts at the current session's workspace, or the home directory when no session is open. The first row is the target row for the whole directory in the input: a directory that is already a workspace is labeled "Existing workspace" and opens a new session directly, an unregistered one says "Create the workspace here", and a path that ends with a separator and does not exist yet says "Create the directory and use it as a workspace", creating the tree first. The directory rows below match the typed segment with a prefix hit ahead of fuzzy hits, dot directories stay hidden until the segment starts with a dot, Tab appends the highlighted directory to the input and lists its contents while a target row ignores Tab, and Enter commits the highlighted row, registers or reuses the workspace, closes the panel and opens a new session in it. Typing `D:` means the absolute path `D:\`; a missing root only reports itself and never tries to create a drive letter. The list caches one directory, so further typing only filters the current directory instead of reading the disk on every key.

Typing `>` shows only application commands, meaning the actions in "Edit shortcuts" whose shortcuts you can customize. Further typing filters by display name or alias; Enter runs the selected command, and commands run recently come first. When a command cannot run right now the panel stays open and the reason it gives appears at the bottom.

Typing `@` shows only files and directories under the current session working directory. Typing just `@` first lists the root entries of the working directory, and further typing filters by path; a / in the query lists that directory directly. On a file row Enter opens a file preview in the right Sidebar, closes the panel and gives focus back to the input that had it before opening; Shift+Enter also opens the preview but gives focus to the Sidebar preview. On a directory row Enter appends "directory/" to the input and the list drills down.

Typing `!` shows only the current session input history, filtered by prompt and answer text. Deleting the leading `!` returns to the session list. Enter writes the whole text back into the session composer with the cursor at the end while the panel stays open; pick another row, or press Esc to close and give focus back. Pressing the "Quick switcher: History" shortcut while the panel is open closes it, and pressing it in another mode switches straight to the history mode.

Typing `#` shows only main panels, meaning the group of full page surfaces in the Sidebar panel list; the ones shipped now are Plugins and Automation tasks, and a main panel registered by another plugin appears on its own. Further typing filters by title or registration id, so both `#插件` and `#plugins` reach Plugins. The gray text under each row title is the registration id, which doubles as the English search term; the main panel currently on screen is labeled "Current", and pressing Enter on it only closes the panel.

Typing `?` or `？` shows only the current session side question records, and "No side questions yet" appears when there are none. Further typing makes all the text after the question mark the question: Enter sends it as a new side question and enters the detail, the answer streams in the list area, the input locks to that question and keeps the question mark you typed (`？` is not rewritten to `?`). The other way round also works: finish the question first and leave the trigger at the end, for example "why?", and the same side question list appears, because the end drops one trigger only and the text before it is the question, so the question in `问题??` is `问题?`. A suffix is transient, so typing more at the end returns to session filtering; no space may follow the trailing trigger; when the start already has `@`, `!`, `+`, `>`, `#` or `?`, the prefix wins and the trailing question mark is ordinary text. Press i, click the locked question box or use the back button at the bottom to return to the list with the question kept in the input, ready to edit and send again; Esc closes the whole panel.

When asking, if the main session is still running the side question carries the text, reasoning and tool activity the current step is producing; when idle it carries only the persisted message history. Images and files ride along by default, and turning off "Include images and files" in Settings leaves placeholders only.

A side question uses the current session model by default, with the reasoning effort pressed down to the lowest level the model supports, which is off on the DeepSeek route; "Side question model" and "Reasoning effort" in Settings can pin it to another model or raise the level, without affecting the main conversation. Regenerating reads the model, level and attachment switch from the current settings instead of replaying the values captured when the question was first asked.

While running, the detail shows "Stop" and "Back", and when finished "Copy", "Regenerate", "Fork" and "Back". The back key is i, and clicking the locked question box works too: it leaves the detail, returns to the list and puts focus back in the input; i works the same while focus is in the locked question box. A plain click leaves the detail, while dragging to select the question text stays, and Tab focus does not leave either. C copies, R regenerates, F forks and S stops only while focus is not in the input, where they are ordinary letters. Backspace no longer goes back. The footer reuses the panel keycap hints and the actions are clickable; with focus in the answer area, the arrow keys, Page Up, Page Down, Home and End scroll the answer the way the browser natively does.

A side question answer goes to the same Markdown renderer as the session panel, so inline code, emphasis, links, tables, strikethrough, task lists, math and code highlighting all match the main conversation. Links take the DSH link color and show a dotted underline on hover; an http(s) link click is handed to the host to open and lands in the system browser on desktop, while a link such as a file path only shows text and opens no file in the panel.

Forking creates a session from the session prefix as of the moment the question was asked, writes the question and the answer at that time into it as one user message, without the pending card text or thinking, then jumps to that session and closes the panel. Closing the panel or refreshing aborts the answer and thinking being generated and keeps the part already received, labeled "Stopped"; records live in browser local storage and survive a refresh.

None of the eight "Quick switcher: ..." commands is bound by default. Go to "Edit shortcuts" in DSH Settings, find the mode and record a combination with a modifier; the other way to search and run them is to pick one in the `>` list.

The session search shortcut can be changed in "Edit shortcuts" in DSH Settings, under the command name "Open quick switcher".

## Behavior

- Session status reads the same unified source the DSH Sidebar uses: waiting for approval, plan awaiting review or waiting for answer shows a warning dot; a running session or subagent shows a spinner; completed unread shows a green dot; idle shows no dot
- While waiting for approval the time slot shows the same short label the Sidebar uses, such as "Approval"
- While subagents run, the parent session shows as running and its status hint carries the running count
- The empty query order of the session list is fixed: the previous session pinned first, then completed unread, pending interaction, running, idle. Outside the pending group, a more recent visit comes first within the same status; the pending group by default puts sessions never opened first (oldest update first among them), then opened ones oldest visit first, so opening a session you cannot act on only moves it back. The previous session means the one visited most recently before the current session, and while you sit on a main panel it is the session you were on last
- Access time is recorded by the plugin itself and kept in browser local storage; a session without a record falls back to its update time, and the time shown on the right of a row is that same sorting time (a pending row shows a short label such as "Approval" in the time slot)
- Only the session on screen in the main area is labeled "Current", and the pinned previous session row is labeled "Previous"; while sitting on a main panel there is no "Current" badge and the pinned row carries only "Previous"
- Once a query is typed the list sorts by match quality, and status shows only through the status dot on the right of the row and no longer affects order
- The five lists share whole query fuzzy matching: a query ignores case and whitespace, and characters hit as soon as they appear in order; the title or display name comes first, and only when it misses does the query match a workspace title, a path, a command alias, a main panel registration id or the question text of a question answer, and those sort after every title hit; session ID is the only exception and matches by prefix, see the next two items
- A session row shows the session ID short code after the time: the first 8 characters after dropping the session- prefix and hyphens; a custom id shorter than 4 characters after normalization shows no short code, so a visible short code always matches
- Session ID matches by prefix only and needs at least 4 characters: it ignores case, hyphens and a leading session-, so pasting the full ID, pasting just its first segment or typing the short code all hit; a slice from the middle does not
- A side question projects the session through the messages the model can see: text, reasoning, tool-call and tool-result all stay; tool calls and results render as text with the tool name, so the request needs no tool declarations
- Tool results go out as user text labeled `[tool result for <tool>]`, and several parallel results merge into one user message; a call still without a result in the current turn is marked `[no result yet]` while running, and a call interrupted in the past is not reported as running
- While the main session runs, a `<LIVE_SESSION_STATE>` live block is appended: the current turn and step, the text and reasoning being streamed, and whether a tool call is being generated; while a tool runs it says there is no streamed output and lists the calls of the current turn that have not returned, with their arguments
- The live block and the pending context are both marked read only; a closing marker with the same name inside the live text is replaced, so it cannot close the block early
- The side question context is read from the pending cards on screen: an approval carries the tool name and reason, and a question or a plan review prefers the structured question; the context travels only with that request, is marked read only, never enters a record and is not shown in the detail
- Side question records live in browser local storage and are kept per session; a record interrupted by a refresh comes back as stopped with its received answer, thinking and effective model
- Each session allows one side question at a time; the record total is governed only by the storage cap
- "Record storage" in Settings defaults to 1 MB and takes any size in MB, where empty or 0 goes back to the default; the control shows the space in use and the cap, plus about how many side questions fit, with an estimate before the first record; past the cap the oldest records are deleted, and "Clear local records" takes two clicks
- The detail status line shows the model, the reasoning effort and usage; running with an empty answer and no reasoning yet shows "Analyzing the request", a stopped answer shows only the status label, and an error shows an error block
- When the model returns reasoning, a collapsible thinking block sits above the answer: collapsed by default, a fixed Think title that shimmers while running, the latest completed paragraph's first line as the preview while streaming and the opening line once settled; expanded, it uses the same Markdown renderer as the answer, and an encrypted `<signature>` prefix is hidden
- Without reasoning the "Analyzing the request" placeholder stays; thinking is for review only: copy takes just the answer, fork writes only the question and answer into the new session, and regenerating clears it
- The answer renders through the DSH session panel Markdown component: GFM tables, bare URLs and angle bracket autolinks, strikethrough, task lists, math and code highlighting all match the main conversation; links take the DSH link color, an http(s) click goes to the host (the system browser on desktop), and file links stay plain text
- Detail and footer copy resolves through the module that owns the view: a key such as `askCopy` comes from the side question module's own dictionary and falls back to core copy when missing, so the detail never shows a raw key name
- The back key in the detail is i, and clicking the locked question box returns the same way: it leaves the detail, returns to the list and gives focus back to the input, keeping the question text; it also works while focus is in the locked question box. Dragging to select the question text and Tab focus do not return; Backspace no longer goes back, and C/R/F/S are still ordinary letters inside the input
- The detail footer reuses the panel keycap hints: actions sit left and Esc to close sits right, the keycaps share the style and font of the list footer, and the buttons themselves draw no border
- A record can be copied, regenerated and forked; regenerating clears the answer and thinking, reads the model, level and attachment switch from the current settings, resends the original question with the pending context currently on screen, and the host rereads the current history and live state; forking uses the session sequence number as of the moment the question was asked and carries neither context nor thinking
- A side question uses the current session model by default, with the lowest reasoning effort that model supports; Settings can pin the side question to another model or raise the effort, without affecting the model and effort of the main conversation
- Each model provides its own reasoning efforts: the DeepSeek route has off, low, high and max, and the pi-ai route adds minimal, medium and xhigh; when a model lacks the chosen effort the nearest lower one is used, and a model without reasoning gets no effort
- The model, effort and attachment switch are read from the current settings for every request, regenerate included; the host returns the model and effort actually in effect in the start event, and the status line shows those actual values
- When the chosen model is already unavailable at ask time, for example because its provider was removed, the host returns 409, the detail error block names that model and points to Settings, and the session model is never swapped in silently
- A provider rejection at call time, such as a failed authentication or an effort that is not accepted at that moment, becomes an error event and keeps the partial answer already received; it is not shown as a finished answer saying "No content returned"
- When the snapshot exceeds the model window the host returns 413 and says it is over the window instead of silently dropping history or truncating the live state; the window is computed for the model the side question actually uses, and attachments do not count toward the character budget
- Settings splits into "Modules", "General" and per module preferences: the module list switches each one, a module that is off is labeled "Off" next to its preference section title while its fields stay editable; General picks the default mode; every section collapses by clicking its title and is expanded by default, and the collapsed state is stored in browser local storage with the preferences; the current preferences are "Pending session order" for sessions and "Side question model", "Reasoning effort", "Include images and files" and "Record storage" for side questions, all stored in browser local storage: the side question model defaults to "Session model", the reasoning effort to "Lowest", the attachment switch is on by default, turning it off leaves images and files as placeholders, regenerating also reads the switch as it is now, and record storage defaults to 1 MB; the order defaults to "Least recently visited first" and can switch to "Most recently visited first", which only affects the pending group
- Module switches live in browser local storage, take effect immediately and sync across tabs; turning one off stops only the runtime contributions, meaning Matchers, Providers, commands, Slots and content views, while copy and setting declarations stay
- The sessions module can be turned off too; doing so leaves the workspace list without its shared data source and stops access time tracking, and Settings spells out both in the description of the sessions row and the dependency warning on the workspaces row
- Workspaces declares a dependency on sessions, which Settings warns about live without turning workspaces off automatically; when every module is off the panel shows "Every module is switched off"
- Each of the eight built in modules registers `quickSwitcher.mode.<模块>` while it is on, labeled "Quick switcher: <mode name>", unbound by default; turning the module off unregisters the command, and turning it back on makes the recorded key overrides take effect again
- Pressing a mode command opens the panel with its seed when closed, closes it when it is already in that mode, and switches in place from another mode
- With no default mode set the first module with an entry wins, which is the session list; when the chosen module is off or unavailable the query falls back to empty, Settings says so live, and the choice is not changed automatically
- The DSH shortcut panel keeps plugin commands inside "Application" and sorts them by id, with no custom groups; this plugin sets its own apart with the "Quick switcher:" label prefix
- Internal subagent activity never enters a side question; developer messages (tool catalog changes) are skipped as unrelated to it
- Text is highlighted only on a title hit; a path, alias, session ID or question text hit produces no highlight; sessions, workspaces, commands, main panels and directory completions cap at 50 rows, history at 200
- Archived sessions, blank drafts and subagent sessions never appear, as they are not switchable user sessions
- A workspace row shows the title, the path and the number of visible sessions in that workspace; the list sorts by the most recent session activity descending, and a workspace with no visible session comes last
- The scope token only holds when a single space follows the workspace title, the title is recognized by longest match, and titles with spaces work too; a plus switches the list only at the very start of the input
- Commands, history, main panels and files only apply when `>`, `!`, `#` or `@` comes at the very start of the input and are ordinary text anywhere else; a side question applies at the start and at the end, and is ordinary text anywhere else
- A side question also accepts compatibility question marks (`？`, `﹖`, `︖`) whose NFKC form equals `?`, both at the start and at the end; the suffix drops only the last character, a trailing space after it means it does not count, and the question in `问题??` is `问题?`
- After asking, the locked input row keeps the trigger character you typed and the end it was on, without normalizing it to the halfwidth form or moving a suffix to the start
- A workspace chosen with Enter remembers its concrete workspace id, so workspaces with the same title never get mixed up
- Shift+Enter on a workspace row writes `=` plus the workspace's parent directory into the input instead of starting a session; starting a session is still available from the scope's "New session" row or by pressing Enter on an existing workspace in `=` mode
- The new-workspace mode only claims a leading `=`; an empty `=` starts at the current session workspace, or the home directory without one, and the start path is written into the input before listing begins
- The target row is the first row and the initial selection; a missing directory is created recursively before registration, a missing root only reports itself, and a file or unreadable path explains the reason without committing
- Directory completion splits at the last separator and segment filtering reads only the cached listing; dot directories stay hidden until the segment starts with a dot, and prefix hits sort ahead of fuzzy hits
- Enter commits the highlighted row, closes the panel and opens a new session in that workspace; Tab only works on directory rows by appending the directory and listing its contents, does nothing on the target row, and Shift+Tab still moves focus
- An existing workspace opens a new session directly: DSH's create is idempotent by path, never registers twice, and keeps the directory name as the title; the plugin offers no rename
- Directory reads go through the plugin host's same-origin endpoints, capped at 500 entries per directory with a note when truncated; DSH's own listDirectory is refused on a native-picker host, so it is not used
- Sessions inside a scope filter with the same rules and the same order as the session mode, and blank drafts and archived sessions never appear
- The command list includes every editable application command DSH announces, including this plugin's own "Open quick switcher" and the eight "Quick switcher: ..." mode commands; read only fixed actions never appear
- A command row shows the shortcut in effect as a capsule on its right, using the same capsule style as the jump hint, and a recently run command also shows a "Recent" capsule
- The command list shows the searchable English aliases under the display name, so a Chinese interface still shows what to type; Chinese aliases remain searchable but are not repeated on the alias line
- Running a command uses the focus from before the panel opened as its context and treats the panel as already closed; a command that depends on focus therefore acts on the earlier focus, not on the panel input
- Recent commands live in browser local storage, capped at 25; another browser or cleared site data starts without them
- Whether a command is available is decided by DSH's own resolve, and the plugin only shows the block reason it returns
- Input history takes only the message window the current session has loaded; after a DSH refresh only the last page is loaded, so earlier input is pulled page by page with "Load earlier input" at the bottom of the list, up to 200
- History collects text the user sent: ordinary prompts, steering interjections and answers to ask_user_question; an answer splits into rows per question, while skipped questions, prompts with only attachments and no text, injected context and subagent messages do not count
- Newest first, and only adjacent duplicate prompts collapse: the same prompt with other content in between counts as separate entries; answers never collapse, because two "yes" answers to two questions in one batch are two real replies
- The draft row is pinned at the top and shows the composer text at the moment the panel opened; it does not appear when the draft is empty, and when the draft equals the newest history entry that entry gives way to the draft row
- A history row is a one line preview with the relative time on the right; a steering row is labeled "Steer" and an ask answer row "Answer"
- Enter only writes the text back into the input and does not close the panel; while the session is sending, the list refuses to fill and gives the reason
- A mode command has no module specific precheck: with no current session, pressing "Quick switcher: History" opens the panel and shows "Open a session in the main area first" instead of returning a block the way the old hand written command did
- The main panel list reads the Sidebar panel list registrations directly, so a main panel registered by a third party plugin appears on its own and disappears when that plugin is uninstalled
- Main panel rows sort by the registration `order` field ascending and keep registration order on ties, matching the Sidebar navigation
- A main panel title recomputes when the interface language changes; a registration without a title falls back to its id
- English search for main panels relies on the registration id with no separate alias table, so an English word missing from the id does not match
- While sitting on a main panel that row is labeled "Current" and Enter only closes the panel; when opening fails the panel stays open and the error shows at the bottom
- Main panels never appear in the default session list, the workspace mode, the command mode, the history mode or the file mode, and do not count toward access time or the pinned row
- Creating a session goes through DSH's own new session entry and follows its blank draft reuse rule
- The file list comes from the DSH file search queried against the current session working directory, and the plugin builds no index; directories such as node_modules, dist and .git are not walked by default, and a hidden file appears only when you type into that directory explicitly
- Typing just `@` lists the workspace root, and a / in the query lists that directory; results cap at 20 and keep the DSH order, only a file name hit is highlighted, and a query with / does not guess file names
- On a directory row Enter appends the path plus a / to the input to keep browsing, and Shift+Enter does the same; on a file row Enter opens the preview and returns to the earlier focus, and Shift+Enter opens the preview and gives focus to the right Sidebar
- The right Sidebar preview opens through a file address that carries the session id, so no absolute path is needed; opening the same file again reuses the existing preview page
- A main panel page has no current session, so `@` only shows a hint; when file search is unavailable or opening fails the panel stays where it is and shows the reason
- Where the mouse rests never affects the selection: hover moves the selection to the row under the pointer only after the pointer really moved; when the list reorders after opening the panel or filtering, a still pointer never steals the keyboard selection
- The first nine rows show the platform's Alt + 1 to Alt + 9 (⌥ 1 to ⌥ 9 on macOS) as a capsule on the right, generated in the currently visible order, and rows from the tenth on show none
- Alt+number runs the matching row directly, the same as Enter; Shift does not change the action, the numeric keypad and combinations with Ctrl or Meta do not count, and AltGr input is unaffected


## Limits

- Only DSH Web is supported today, not a plain TUI
- Depends on the Slot hooks and components the DSH client exposes: `useSessionStatus`, `useSessions`, `useWorkspaces`, `usePanelInfo`, `useChat`, `useInput`, `useSession` and the official `StateDot`; a DSH rename needs a regression pass
- The main panel list depends on `ctx.slots.entriesOfSlot("sidebar.panellist")` and `ctx.layout.selectPanel(id)`; the plugin resolves all three forms of a panel label, a string, a function and a language map
- File search depends on `ctx.get("remote.fileReferences")`, and opening and previewing a file depend on `ctx.get("sidebarRight").openResource` and a `dsh-resource://file/session/...` address; when missing, only the file mode reports an error
- The command list reads the catalog and config of `ctx.shortcuts`, and running reads the command object in the registry and calls resolve; the latter is not a public DSH API
- Input history depends on the standard props of `conversation.input.overlay` and on `sessions.binding(id).session.loadOlder()`; question answers depend on the `question-reply` node and the `questions`/`answers` shape
- Creating a session depends on `uiWorkspace.startSession`, which DSH before 0.2.2 does not have
- Creating a workspace depends on the client service `workspaces.create`, `uiWorkspace.startSession`, and the plugin host's two same-origin endpoints `/dsh-quick-switcher/paths` and `/dsh-quick-switcher/paths/mkdir`; when the host half is not loaded, a service is renamed or an endpoint is refused, that mode reports the failure and the other modes keep working
- Directory completion lists directories only, never files; a path must be absolute, a relative text resolves against the starting directory, and an empty starting directory only asks for an absolute path
- Side questions depend on `webServer`, `agents`, `llm` and `sessionController` on the host side; the stream events and host routes are the plugin's own protocol, so the host and the client must be on the same version
- Rendering a side question answer reuses `MarkdownText` from `@deepseek-ai/dsh-client-ui-primitives` and its labels shape (code block copy and wrap, footnotes); a DSH rename or labels change needs a regression pass
- Links inside a side question answer are not intercepted: http(s) goes to the host window opening logic and lands in the system browser on desktop; a link such as a file path only shows text and opens no file in the panel
- The side question model catalog comes from `ctx.get("remote.session").modelCatalog()`; while the service is not ready only "Session model" or the saved model can be chosen, and when one provider's list fails it is named inline without blocking the other settings
- A side question validates the chosen model through `llm.resolveModelInfo`, reads its context window and efforts, then hands the result to `llm.stream`; reasoning effort ids come from each provider adapter, the plugin only compares and steps down in the order off, minimal, low, medium, high, xhigh, max, and an unknown effort sorts after the known ones in adapter declaration order
- The side question context depends on the DOM selectors of the approval card, the question card and the plan review card; when DSH changes a selector the context turns empty and the question still goes out
- A side question is modal: while the panel is open the approval and question cards cannot be clicked; closing the panel or refreshing aborts the answer and thinking being generated and keeps the part already received
- Side question records live in browser local storage and survive a refresh; forking requires a build that provides `sessionController.fork`, otherwise the host returns 501
- Two DSH windows write their own record snapshots, so the later write replaces the earlier one; the cap is measured from the text browser storage holds, and a single running record may exceed it until it settles
- The suffix trigger belongs to side questions only; the other modes still only read the start, so the trailing question mark in `@file?` is just part of the filter. A suffix is transient and typing after it returns to session filtering; no space may follow the trailing trigger, so `问题? ` never enters a side question
- The suffix drops one trigger only, and the question in `问题??` is `问题?`; after asking, the locked input row keeps the suffix as typed, and the mode command treats both spellings as the same ask
- The file result cap, ignored directories and index cap are decided by the DSH fileReferences configuration; in other modes Tab still moves focus, while the `=` mode's directory list claims it
- Archived sessions, blank drafts and subagent sessions never appear; a session ID only matches a prefix of at least 4 characters after normalization, and a short code is shown only for an id of at least 4 characters after normalization
- Access time starts recording after the plugin is installed; clearing site data falls back to update time, and without visit history the previous session cannot be determined
- Settings, module switches and the default mode live only in browser local storage and return to their defaults in another browser or after cleared site data; a value the host needs can only travel with the request
- Module switches are saved by module id; when an external module is uninstalled and installed again its state returns, and a key saved during a long uninstall triggers no action
- Turning a module off stops only its client runtime contributions; the side question host routes stay registered, the client simply stops calling them
- A module entry seed must land on its own Matcher; the manifest test guarantees it for built in modules, and an external module that gets it wrong opens another mode
- A mode command has no module specific precheck: with no current session, the history command opens the panel and shows a hint
- The DSH shortcut panel offers no command groups, so plugin commands always sit under "Application" sorted by id and can only be told apart by their label prefix
- Turning the side question module off releases its mount surface, which aborts a side question being generated, keeps the received answer and thinking, and writes them to browser local storage; turning it back on restores them
- Modules cannot import each other; shared data goes through a named store, and a wrong name only reads null
- The public service covers the client only and has an apiVersion of 1; host endpoints and the host registry are not exposed
- Module settings support four field types, boolean, choice, number and custom; a custom control needs the module to provide render itself
- When no main panel is registered the `#` list shows "No panels available" instead of falling back to the session list
- The command list does not show fixed read only actions and cannot rebind them
- Input history covers only the message window the session has loaded, and earlier input is pulled page by page with "Load earlier input", 50 to 500 messages at a time
- Approvals and plan reviews only have click actions and no text to write back, so they never enter input history
