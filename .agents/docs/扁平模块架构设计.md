本文是 dsh-quick-switcher 1.0.0 的模块架构设计。目标是让本体只认识一套统一接口，七个现有模式全部变成垂直模块，同时把设置、文案、命令、槽与内容视图纳入客户端模块契约，宿主端点由独立的一份宿主模块契约承担。

设计与 0.8.0 的用户可见行为严格对齐，只清理内部泄漏。所有实现阶段以本文为准，最终偏差汇总在文末的实施偏差一节。

1.1.0 在这份契约上增加模块开关、模块入口、模块依赖与默认打开模式，见「模块开关」与「模块入口」两节；本体仍然不认识任何具体前缀或领域投影。

### 目标

这次重构要同时解决四件事：把本体从所有具体模式里解耦、让一个特性的所有贡献落在同一个模块目录、给设置与文案一条统一的注册路径、把注册口开放给其他客户端插件。

- 本体不认识任何具体前缀、领域投影或具体行，连会话也不行
- 一个模块是一个垂直特性，匹配器只是它交上来的贡献之一
- 设置、文案、命令、槽与内容视图从客户端模块声明里来，宿主端点从宿主模块声明里来
- 其他客户端插件可以通过公开服务注册模块，接口带版本号
- 现有行为不变，测试与构建在每一阶段都可运行

### 术语

本体:
注册中心、面板外壳、通用行与键盘、设置存储与设置页、文案合并、宿主装配与公开服务。它只认识模块接口。
_Avoid_: 核心, 框架, 引擎

模块:
一个垂直特性，声明匹配器、挂载面、设置、文案、命令、槽与内容视图。会话、工作区、命令、历史、主面板、文件、侧问各是一个模块。
_Avoid_: 插件, 路由, 模式包

挂载:
每次打开面板时为一个模块创建一份实例，返回本次挂载的匹配器与 Provider，面板关闭时逆序释放。
_Avoid_: 初始化, 启动, 实例化

匹配器:
模块交给本体的查询认领函数。它收到查询与面板上下文，返回自己的状态或 null；本体按优先级找到第一个认领者。
_Avoid_: 路由, 处理器, 模式

静态能力包:
模块声明函数在插件加载时收到的一份能力，包含模块 id、文案、设置读写、面板控制器、共享 store、DSH 服务与日志。它跨面板挂载稳定。
_Avoid_: 上下文, ctx, 依赖

面板上下文:
每次打开面板时传给挂载面与匹配器的上下文，包含当前会话与主面板 id、待处理交互、当前时间、面板动作与能力包。它随面板挂载创建与销毁。
_Avoid_: 运行环境, 会话上下文

视图渲染器:
模块按 kind 注册的 React 组件，用来替换列表区或底栏。本体按 kind 查表，不认识侧问这类具体视图。
_Avoid_: 详情组件, 自定义视图, 插槽

设置分组路径:
模块设置的寻址方式，形如 `[模块, 分组?, 字段]`。分组可省略，字段 id 在模块内唯一。
_Avoid_: 设置键, 配置路径, 命名空间

共享 store:
模块之间按名字共享的可订阅快照，未发布时读出 null；它让一个模块拥有的数据被另一个模块读取，而不用互相 import。
_Avoid_: 全局变量, 事件总线, 服务单例

公开服务:
本体在客户端上下文提供的 `quickSwitcher` 服务，`apiVersion` 为 1，向其他客户端插件开放模块注册与面板控制。
_Avoid_: 插件 API, 外部接口, 扩展点

宿主模块:
只在宿主半区装配的模块，贡献 webServer 路由与事件订阅。它不在公开服务的范围内。
_Avoid_: 服务端模块, 后端插件

模块开关:
本体持有、按浏览器保存的模块启停状态。关闭只停运行贡献，保留文案与设置声明。
_Avoid_: 启用状态, 模块配置, 禁用状态

运行贡献:
模块在运行中实际参与的部分，包含命令、槽、内容视图与每次面板挂载。模块开关只停这一层。
_Avoid_: 动态贡献, 副作用

声明贡献:
模块的文案与设置声明。模块关闭时仍然保留，设置页因此仍能显示它的标题、说明、开关与偏好。
_Avoid_: 静态贡献, 元数据

模块入口:
模块声明的查询种子与模式显示名，本体据此自动注册一条模式命令，并把该模块列为默认打开模式的候选。
_Avoid_: 路由, 前缀, 触发词, 入口路由

模式命令:
由模块入口自动注册的应用命令，id 为 `quickSwitcher.mode.<模块>`，按下时打开、切换或关闭面板到该模式。
_Avoid_: 直达快捷键, 快捷方式, 路由命令

默认模式:
通用打开快捷键在没有显式种子时进入的模式，由设置页选择；未选择时取第一个带入口的模块。
_Avoid_: 默认页, 首页

模块依赖:
一个模块声明的数据来源模块，设置页据此在来源被关闭时给出警告，但不自动联锁。
_Avoid_: 依赖注入, 强依赖

### 本体边界

本体保留且只保留这些职责：

- 注册中心：模块登记、校验、排序、订阅、挂载与释放
- 面板外壳：开关、输入、选中、键盘、悬停、直达提示、焦点恢复、提示与错误、行列表渲染
- 通用行组件、指针基线与数字直达
- 设置存储、设置页与三种通用控件
- 文案合并与翻译函数
- 面板控制器与公开服务
- 宿主注册中心
- 共享纯函数：模糊匹配、时间、id、路径

本体不出现具体前缀、领域投影、具体行或具体详情。七个现有模式全部迁入 `src/modules`。

唯一的领域例外是面板上下文里的当前会话 id 与待处理交互快照。文件、历史与侧问都要用当前会话，而这是「面板在什么上面工作」，不是会话列表的投影。本体从 DSH 的会话钩子里取这两项，不计算会话条目、排序、访问时间或状态。

### 模块形状

模块是一个声明函数，加载时执行一次，收到静态能力包。声明返回的 `mount` 在每次打开面板时执行一次。

```js
// src/modules/files/client.js
import { defineModule } from "../../core/module.js";

export default defineModule("files", (api) => {
  return {
    apiVersion: 1,
    order: 50,
    labelKey: "filesTitle",
    descriptionKey: "filesDescription",
    dependencies: [],
    entry: { seed: "@" },
    locale: {
      zh: { filesTitle: "文件", filesDescription: "…" },
      en: { filesTitle: "Files", filesDescription: "…" },
    },
    settings: { /* 见模块设置 */ },
    commands: [ /* 见文案与命令 */ ],
    slots: [ /* 见槽与观察器 */ ],
    views: { /* 见内容视图 */ },

    mount(panel) {
      const cache = new Map();
      return {
        providers: [FilesProvider],
        matchers: [
          {
            id: "files",
            priority: 10,
            match: (query, panel) =>
              query.startsWith("@")
                ? { filter: query.slice(1), sessionId: panel.currentSessionId }
                : null,
            view: (state, panel) => ({ /* 统一视图 */ }),
          },
        ],
        dispose() {
          cache.clear();
        },
      };
    },
  };
});
```

`defineModule` 校验 id 与声明函数，返回一份可直接注册的模块定义。声明函数的返回值在注册时校验，校验失败抛错。

### 静态能力包

能力包在插件加载时构造一次，跨面板挂载稳定。

```js
{
  id: "files",
  t(key, params),
  services: { slots, locale, shortcuts, sessions, uiWorkspace, layout },
  get(name),
  settings: { get(id), set(id, value), subscribe(listener) },
  panel: {
    open({ seed }),
    close(),
    toggle(),
    isOpen(),
    getState(),
    subscribe(listener),
    list(),
  },
  shared: { store(name) },
  effect(callback, label),
  log: { info, warn, error },
}
```

- `t` 先查模块自己的字典，再查本体字典
- `settings.get` 只在模块登记之后返回声明里的默认值；声明期间不要读取设置
- `panel` 是跨挂载稳定的控制器，命令与 Provider 都用它
- `shared.store` 取得一个命名快照，供另一个模块读取而不用 import 它
- `effect` 转交给宿主上下文，模块卸载时自动释放
- `services` 是本体注入过的 DSH 服务；需要可选服务时用 `get(name)`

### 挂载面

`mount(panel)` 返回本次面板的挂载面。

```js
{
  providers: [FilesProvider],
  matchers: [ /* 匹配器 */ ],
  dispose() {},
}
```

- `providers` 按模块 `order` 嵌套渲染在面板内容外层，收到 `{ instance, panel }`
- `matchers` 是本次挂载的匹配器实例
- `dispose` 在面板关闭时按逆序调用
- 挂载面上除这三个键以外的字段原样保留，作为 `instance` 交给该模块的 Provider 与内容渲染器，详情组件因此能拿到模块自己的 store 与动作
- 模块可以没有匹配器，只贡献设置、命令、槽或内容视图

### 匹配器

匹配器是函数，不是前缀字段。前缀由本体提供的 `prefixMatcher` helper 生成，后缀、正则与整句语义由模块自己写。

```js
{
  id: "history",              // 全局唯一，也是控制器里的模式 id
  priority: 20,               // 数字越大越先认领，默认 0
  match(query, panel) {       // 返回 null 表示不认领
    return query.startsWith("!") ? { filter: query.slice(1) } : null;
  },
  view(state, panel) {
    return { /* 统一视图 */ };
  },
}
```

解析顺序是 `priority` 降序、模块 `order` 升序、声明顺序。第一个返回非 null 的匹配器独占本次视图，其余匹配器不参与。不做合并、分节或全局行 key 校验。模式由外壳在每次解析后通过控制器发布，匹配器不需要自己声明。

`prefixMatcher("@", { id: "files", priority: 10, map, view })` 生成一个带 `match` 的匹配器；`map` 决定状态的形状，省略时是 `{ filter }`。会话模块用空前缀与最低优先级兜底。

### 统一视图

视图是同步投影，异步结果由模块自己的 store 发布，再调 `panel.notify()` 请求重渲染。

```js
{
  placeholder,
  searchAria,
  listLabel,
  rows: [
    {
      key, title, positions, meta, className, titleClassName,
      icon, keys, badge, status, trailing, action,
      run(), shiftRun(),
    },
  ],
  emptyText,
  note,
  hints,
  count,
  load?(),
  content?: { kind, props },
  footer?: { kind, props },
  inputLocked?: boolean,
  keydown?(event, panel),
}
```

- `run` 与 `shiftRun` 是模块自己的闭包，直接执行动作，不返回效果描述符；本体在 try/catch 里调用
- `action: true` 表示这一行不参与打字后的初始选中，沿用「新建会话」与「加载更早」的语义
- `content` 与 `footer` 按 kind 到渲染器表里取组件
- `keydown` 只在内容视图展示时先于本体键盘处理调用，返回 `true` 表示已处理
- `load` 在渲染后调用一次，用来发起异步查询
- 行 `key` 在本次视图内唯一；重复时校验抛错，注册中心记录后回退到下一个匹配器或本体默认视图
- 行不再有 `current` 字段，它没有运行时读取者

### 模块设置

设置按模块分组声明，路径是 `[模块, 分组?, 字段]`，分组可省略。

```js
settings: {
  labelKey: "settingsFilesLabel",
  descriptionKey: "settingsFilesDescription",
  groups: [
    {
      id: "search",
      labelKey: "settingsFilesSearch",
      fields: [
        {
          id: "maxResults", type: "number", default: 20,
          min: 1, max: 200, step: 1,
          labelKey: "settingsMaxResults",
          descriptionKey: "settingsMaxResultsDescription",
          hintKey: "settingsMaxResultsHint",
        },
        { id: "includeHidden", type: "boolean", default: false, labelKey: "..." },
        {
          id: "order", type: "choice", default: "recent",
          options: [{ value: "recent", labelKey: "..." }],
        },
      ],
    },
  ],
}
```

- 支持 `boolean`、`choice`、`number` 三种字段，特殊控件用 `type: "custom"` 加 `render`；`render` 返回 React 元素，可以返回一个组件元素并闭包捕获模块 api，因此能读远程数据或跟随另一个字段的值
- 字段 id 在模块内唯一，跨分组也不能重复
- 本体持有一份 localStorage 文档，深合并写入并保留未知字段，存储键仍是 `dsh.quick-switcher.v1`
- 旧的两个平铺偏好迁移为 `ask.includeAttachments` 与 `sessions.pendingOrder`，未知旧字段原样保留
- 设置页仍是一个 `settings.section`：顶部「模块」列表逐个开关，其次「通用」选择默认模式，然后按模块分节放偏好；模块注册、注销或开关时页面跟随刷新
- 设置页的三个分区可折叠，展开状态存在 `__core.expanded`，默认展开；折叠状态和偏好一样按浏览器保存
- 设置值在读取时校验，非法值回落到默认值

### 模块开关

模块开关是本体持有的运行期状态，按浏览器保存在设置文档的保留子树 `__core.switches` 里；关闭只停运行贡献，文案与设置声明保留。

- 关闭时注销命令、槽与内容视图，并释放当前挂载面；匹配器不再参与解析
- 设置页仍显示模块标题、说明、开关与偏好，偏好可以预先调整；偏好分区标「已关闭」
- 开关在设置页、另一个标签页与运行中注册的模块上都立即生效；全部关闭时面板显示空状态提示
- 模块可以声明 `dependencies`；依赖关闭时设置页实时警告，但不自动联锁；静态依赖行不常驻，避免把开关列表撑高
- 会话模块也可以关闭；它的观察器同时是工作区列表的数据源，关闭后工作区列表为空、访问时间停止记录
- 外部模块一视同仁：开关按模块 id 保存，模块暂时卸载时状态保留，重新注册后恢复
- 启动时注册中心用 `isModuleEnabled` 判断是否应用运行贡献；重新打开失败时回滚并保持关闭

### 模块入口

入口是模块声明的一条自描述，形如 `{ seed, mode?, labelKey?, aliases?, defaults? }`；本体据此自动注册一条 `quickSwitcher.mode.<模块>` 应用命令，并把它列为默认模式的候选。

- `seed` 是输入框里预填的查询，必须能解析回自己的匹配器；会话用空种子表示默认列表
- `mode` 是面板控制器发布的匹配器 id，默认等于模块 id；命令据此判断是否已经在目标模式
- 标签是「快速切换器：<入口名>」，入口名取 `entry.labelKey`，退回模块 `labelKey`，再退回模块 id
- 别名包含模块 id、入口名与模块标题的中英文本，供快捷键面板搜索；默认键为空，入口也可以用 `defaults` 自带键位
- 行为：面板关闭就打开并播种；已在同一模式就关闭；在其他模式就原地重播种
- 模块关闭时命令注销，重新开启时以同一 id 注册，DSH 已保存的键位覆盖仍然生效
- 历史模块不再手写命令，旧的 `quickSwitcher.history` 删除；当前没有用户依赖它，不做键位迁移
- DSH 快捷键面板不开放命令分组：插件命令固定进「应用操作」，按 id 排序，可见区分只能靠标签前缀

### 默认模式

默认模式决定通用打开命令从关闭变为打开时预填哪个 `seed`；它由设置页的「通用」分区选择，保存在 `__core.defaultMode`。

- 未选择时取第一个带入口的模块，当前是会话列表
- 显式带 `seed` 的调用不经过默认模式，模式命令与其他插件的 `open({ seed })` 都算显式
- 所选模块关闭或未注册时回退空查询，设置页实时提示，不自动改选；模块重新开启后自动恢复
- 公开服务的 `panel.open()` 与 `panel.toggle()` 没有 `seed` 时同样使用默认模式

### 文案与命令

每个模块自带中英字典，键在模块内命名，不写前缀。本体合并时按模块 id 隔离，`api.t` 先查模块字典再查本体字典。

命令沿用 DSH 的 `ctx.shortcuts.register` 元数据，`label` 用 thunk 捕获 `api.t`，`resolve` 闭包捕获能力包。打开面板的命令归本体，模式命令由本体按模块入口自动注册，模块自己声明的命令仍然照常登记。命令随模块注册、开关与注销增删，本体负责释放。

### 槽与观察器

模块可以声明任意 DSH 槽贡献，本体用 `ctx.slots.inject` 延迟注册并在卸载时释放。

```js
slots: [
  {
    name: "conversation.input.overlay",
    id: "dsh-quick-switcher-history",
    order: 10,
    inject: () => ({ historyStore, loadOlder }),
    component: HistoryBridge,
  },
]
```

历史桥接与访问时间观察器都走这里。观察器注册在 `shell.overlay` 上，面板关闭时仍然挂着，因此访问时间可以在侧栏切会话时继续记录。

### 共享 store

一个模块拥有、另一个模块只需要读取的数据走命名共享 store，不靠模块间 import。总线只有 `store(name)`：同名取得同一个可订阅快照，未发布时读出 null，发布与订阅由使用方自己调。

会话模块发布 `session-data`，里面有可见会话条目、当前会话 id、工作区行与一个行构建函数；工作区模块读同一份数据来渲染作用域列表。名字写错只会拿到空快照，不会让模块图成环。

### 内容视图

模块按 kind 注册内容与底栏渲染器，本体不认识具体视图。

```js
views: {
  ask: { content: AskDetail, footer: AskFooter },
}
```

- kind 全局唯一，冲突在注册时抛错
- 渲染器收到 `{ descriptor, instance, panel, t }`
- `descriptor.props` 由模块在视图里生成，可以带闭包
- 内容视图的字母键由模块的 `keydown` 处理；本体的 Escape 与 Tab 在模块之前处理，方向键、Home/End 与数字直达不在内容视图里生效
- `inputLocked` 与 `keydown` 只对当前认领的视图生效

### 宿主模块

宿主模块只在宿主半区装配，声明函数在 `apply` 时执行一次。

```js
// src/modules/ask/host.js
import { defineHostModule } from "../../core/host/module.js";
import { ASK_PATH, FORK_PATH } from "./shared.js";

export default defineHostModule("ask", (api) => {
  const running = new Map();
  const live = createLiveState();
  return {
    routes: [
      { path: ASK_PATH, handler: (req, res) => askRoute(api, running, live, req, res) },
      { path: FORK_PATH, handler: (req, res) => forkRoute(api, req, res) },
    ],
    listeners: [
      { name: "agent/assistant-stream", handler: (event) => live.accept(event) },
    ],
    dispose() {
      running.clear();
      live.clear();
    },
  };
});
```

宿主能力包是 `{ id, webServer, agents, llm, sessionController, on, effect, log }`。宿主注册中心只在 `src/modules/host-manifest.js` 里装配本插件内部模块，公开服务不覆盖宿主侧。

客户端与宿主共用的路径、事件名、字段名与卸载文案放模块自己的 `shared.js`，两边 import 同一份。

### 公开服务

本体在客户端上下文提供 `quickSwitcher` 服务，注册在 `ctx.effect` 里，卸载时移除。

```js
{
  apiVersion: 1,
  register(definition): () => void,
  panel: {
    open({ seed }),
    close(),
    toggle(),
    isOpen(),
    getState(),
    subscribe(listener),
    list(),
  },
}
```

消费方这样使用：

```js
export const inject = ["quickSwitcher"];

export function apply(ctx) {
  const dispose = ctx.quickSwitcher.register(
    defineModule("my-mode", (api) => ({ /* 模块声明 */ })),
  );
  ctx.effect(() => dispose);
}
```

- `register` 校验模块定义与声明，返回注销函数
- 定义可以直接写成 `{ id, setup }`，`defineModule` 只做 id 与函数的早期校验
- 模块声明可以带 `entry`、`descriptionKey` 与 `dependencies`：入口让本体自动注册模式命令并列入默认模式，说明与依赖进入设置页
- `panel.open` 不带 `seed` 时进入默认模式；显式 `seed` 不受影响；`list` 报告每个模块是否启用
- 面板打开期间注册或注销，只增删受影响模块的挂载面，保留查询、选中与其他模块的运行中状态
- 注册顺序不影响匹配结果，`priority` 与模块 `order` 决定顺序
- 服务只覆盖客户端；宿主端点仍由本插件内部模块贡献

### 冲突与错误

公开接口的失败要能被调用方接住，内部模块的失败不能拖垮面板，所以校验放在注册时，渲染期只做隔离。

- 模块 id、匹配器 id、视图 kind 全局唯一
- 字段 id 在模块内唯一；设置分组 id 在模块内唯一
- 关闭模块的视图 kind 仍然占位，另一个模块不能声明同名 kind
- 这些冲突在注册时抛错，公开服务的调用方自己接住
- 内部模块逐个装配，单个失败记录后跳过；契约测试在跑测试时暴露失败
- `match`、`view`、`mount` 抛错由注册中心记录并跳过；`keydown`、`load` 抛错由外壳按匹配器记录一次后继续，面板保留可用的默认视图
- 开关重新打开时命令、槽或视图注册失败会回滚并保持关闭，记录日志，面板不受影响

### 生命周期

静态贡献只发生一次，动态贡献跟着面板开合与模块开关走，两层之间的边界是 `mount`。

1. 插件加载时构造设置存储、翻译器、面板控制器与服务，读取已保存的模块开关，登记内部模块
2. 模块声明函数执行，文案与设置声明被登记；命令、槽与视图只在模块开启时应用，`api.effect` 的回调立即执行
3. 面板打开时，按 `order` 调用每个已启用模块的 `mount`，收集 Provider 与匹配器
4. 每次查询变化，按优先级调用匹配器，第一个认领者的视图被渲染
5. 面板关闭时逆序调用挂载面的 `dispose`，再恢复焦点
6. 模块关闭或注销时释放运行贡献与当前挂载面；关闭保留文案与设置声明
7. 插件卸载时注销全部模块、移除公开服务、释放设置存储与控制器

### 迁移阶段

新代码先在 `src/core` 与 `src/modules` 里并行建成，旧入口在最后一步之前不动，因此每个阶段结束时插件仍按旧实现运行，测试与构建全绿；最后一步才切换入口并删除旧层。这样不需要写一个新旧并存的兼容适配器。

阶段一:
模块声明、注册中心、匹配器解析、设置存储、文案合并与契约测试，不接具体模块。

阶段二:
面板外壳、控制器、通用行与键盘，用两个假模块验证挂载、查询切换与释放。

阶段三:
会话、工作区、命令、主面板与文件五个行类模块，连同它们的数据投影与测试。

阶段四:
历史与侧问模块，包含桥接槽、内容视图渲染器、详情按键与客户端侧宿主调用。

阶段五:
宿主注册中心、侧问宿主模块与 shared 协议；设置页改为按模块声明生成，文案按模块拆分。

阶段六:
切换 `src/plugin.js` 与 `index.js` 入口，删除旧路由、旧数据层与旧面板，重写测试与 README，版本升到 1.0.0。

### 实施偏差

实现过程中的偏差按阶段记录在这里，每条写明原因与最终形状。

- 行类模块的数据走模块 store 或槽观察器，例如会话数据必须随面板关闭继续更新；面板挂载面里的 Provider 留给需要 React 上下文的视图，外壳仍按模块 order 嵌套 Provider
- 会话模块把 `rowFor` 放进 `session-data`，工作区作用域借它渲染同一套会话行，避免复制行构造
- 面板上下文额外暴露 `activePanelId`，主面板模块用它标「当前」；这与当前会话 id 一样属于「面板在什么上面工作」
- 历史模块在面板挂载时冻结草稿，与原对话框打开时冻结的时机一致
- 设置页由一个通用组件按模块声明生成，字段只支持 boolean、choice、number 与 custom；模块注册时页面跟随刷新
- 宿主半区使用只认 `routes`、`listeners` 与 `dispose` 的注册中心，`index.js` 只做装配；侧问宿主整体迁入 `src/modules/ask/host.js`
- 公共协议文件 `src/modules/ask/shared.js` 由客户端与宿主共用路径、卸载文案与 SSE 事件名，两半不再各写一份常量
- 旧实现最后整体删除，`client.js` 由新的 `src/plugin.js` 重新打包；模块文案内联进各自 locale 文件，旧共享字典与 `locale-slice` 一并删除
- 侧问模块把 store、ui 与 actions 放在挂载实例上，详情与底栏渲染器通过 `instance` 读取；这是挂载面保留额外字段的第一个真实用例
- `core/panel/styles.js` 仍保留各模式的行与详情类名样式，作为面板的视觉层；把样式注册下放给模块需要新增接口，本次未做，留作后续
- 设置页按模块分组后，原来的两个偏好分别出现在「会话」与「侧问」两组下，字段与文案不变

1.1.0 的偏差与补充:

- 模块开关与默认模式存在同一份 localStorage 文档的保留子树 `__core` 下；模块 id 不能以 `_` 开头，因此这个子树不会与任何模块路径相撞
- 注册中心把贡献拆成「声明贡献」与「运行贡献」两组：开关只重放后者，前者始终保留，设置页才能在模块关闭时继续显示开关与偏好
- 模块入口命令由注册中心生成，id 为 `quickSwitcher.mode.<模块>`；历史模块的手写命令删除，旧的 `quickSwitcher.history` 不再保留，当前没有用户依赖旧 id
- 设置页的纯投影抽到 `core/settings/model.js`，默认模式回退抽到 `core/lib/default-mode.js`，两者都用 node --test 直接覆盖，不需要 React
- 设置页结构改为「模块」开关列表、「通用」默认模式、各模块偏好三段；关闭模块的偏好分区保留并标「已关闭」；默认模式用横向胶囊，模块行只保留一句说明，依赖只在实际关闭时出现警告；三段可折叠，展开状态存在 `__core.expanded`
- DSH 快捷键面板把插件命令固定收进「应用操作」且不支持自定义分组，生成的命令只能用统一标签前缀与 id 排序区分，见 0022
